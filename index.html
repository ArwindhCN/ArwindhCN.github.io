Code, methodology and experiment log ↗

Match each of 1.7M businesses to every record of the same business among 10M records from two other sources. Names arrive with typos, abbreviations, reordered addresses and Indian scripts, and one test country (France) never appears in training. The metric is macro F0.5, so a false match costs twice as much as a missed one.

What moved the score

  • Rarity-based blocking over a packed index. Keys come from each record's rarest words. A 40-bit key hash and a 24-bit record ID share one sorted uint64 array per country, so every lookup is a binary search.
  • Bidirectional blocking with a hub cap. Searching backwards from every S2/S3 record lifted candidate recall from 0.953 to 0.971. The cap stopped one business from collecting 142,645 candidates through the word "com".
  • A fine-tuned transformer as one feature. A 22.7M-parameter MiniLM cross-encoder, fine-tuned in folds split by entity so it never scores entities it trained on. Alone it scored 0.961; as a LightGBM feature it added +0.005.
  • Learned transliteration. A 1,305-word Indian-script to Latin dictionary learned only from training pairs. Median name similarity on true pairs went from 0.10 to 1.00.
  • An expected-F0.5 decision layer. Each record goes to at most one business, then each business keeps the candidate subset that maximises expected F0.5, including predicting nothing.

I logged what failed too. A three-model LightGBM ensemble scored 0.9660 against 0.9661 for one model. Half precision on the Apple GPU was slower (435 vs 548 pairs/s). Error analysis on v7 showed 41.5% of remaining errors were true matches that never reached the candidate set, which is why later versions went after recall in blocking.

Five anti-obesity drugs (semaglutide, liraglutide, tirzepatide, orlistat, phentermine) do not suit every patient equally. Type 2 diabetes, cardiovascular disease or chronic kidney disease changes which one is safest and most effective. The model has to rank them for each patient and agree with what large clinical trials established.

Auditing my own pipeline

A perfect score is a reason to look harder. Before trusting it, I audited the labels and features for ways the model could be learning my assumptions instead of the evidence.

FoundHand-written base scores ranked one drug first in every cohort before any patient was seen. The GNN was learning an opinion.
FixedBase scores derived from trial outcomes: weight loss, HbA1c change, adverse events and discontinuation, weighted equally.
FoundTextbook lab thresholds almost never fired. 98.6% of patients sat below the HbA1c cut-off, so lab features barely affected labels.
FixedThresholds calibrated to the cohort's own percentiles, so labs can change a ranking for edge cases.
FoundSynthetic HbA1c values below 4.0%, which is not possible in a living person.
FixedPhysiological clamping to 4.5–15.0% before any computation.
FoundImputed trial rows counted as much as real RCT results, and a contraindicated drug still scored as an option for CVD.
FixedImputed rows down-weighted in the loss, contraindications enforced, and every output labelled RCT, imputed or contraindicated.

Ablation studies on within-group personalization then set the boundaries of what graph-based decision support can claim here. Research prototype on synthetic patients, not for clinical use.
